1. Theoretical Background & Foundations
In previous laboratory sessions, your exploration of Adversarial Search focused entirely on deterministic, perfect-information environments. Using the Minimax algorithm and Alpha-Beta pruning, agents operated under the rigid assumption that every decision leads strictly to a definitive, fully foreseeable game configuration. In games like Chess or Tic-Tac-Toe, if an agent executes a move, the resulting state is guaranteed.
However, real-world scenarios and many classic games (e.g., Backgammon, Monopoly, Poker, or localized tactical scenarios involving environmental failures) introduce uncertainty. This uncertainty can stem from dice rolls, card shuffles, weather conditions, or unexpected mechanical slippage. In AI terminology, these are classified as Stochastic Games.
1.1 The Structural Evolution of Game Trees
To model uncertainty, we must introduce a third node type into our state-space architecture: The Chance Node. The game tree now alternates between three layers rather than two:
1. MAX Nodes (Triangles pointing Up / Rectangles): Represent the AI agent's turns. The objective remains unchanged: maximize the utility propagated from the lower layers.
2. MIN Nodes (Triangles pointing Down / Circles): Represent the perfect opponent's turns. The objective remains unchanged: minimize the utility to sabotage the AI.
3. CHANCE Nodes (Circles or Diamonds with distinct labeling): Represent nature, environment, or a randomizing device (e.g., dice roll). These nodes do not make strategic choices; instead, they branch into multiple possible states based on a set probability distribution.
1.2 Mathematical Formulation of Expecti-Minimax
V(node) = Static_Utility(node)   [If Terminal State]V(node) = max_{c ∈ Children} V(c)   [If MAX Node]V(node) = min_{c ∈ Children} V(c)   [If MIN Node]V(node) = ∑_{i} P(child_i) × V(child_i)   [If CHANCE Node]
Where P(child_i) represents the precise probability of a specific random outcome occurring, and ∑ P(child_i) = 1.0.
1.3 Deep Breakdown of the Algorithm Logic
When the algorithm encounters a Chance Node during backtracking, it does not pick the minimum or maximum score. Instead, it computes the Expected Value (or mean value) of all the sub-branches. This forces the MAX player to play optimally relative to the odds. If a certain high-reward path has only a 1% chance of succeeding, the expected value will reflect that risk, pushing the AI toward a safer, higher-probability branch.
1.4 Expecti-Minimax Pseudocode Framework
function EXPECTIMINIMAX(node, depth, nodeType):    if depth == 0 or node is terminal:        return static_utility_value(node)            if nodeType == "MAX":        maxEval = -infinity        for each child in node.children:            eval = EXPECTIMINIMAX(child, depth - 1, "CHANCE")            maxEval = max(maxEval, eval)        return maxEval            elif nodeType == "MIN":        minEval = +infinity        for each child in node.children:            eval = EXPECTIMINIMAX(child, depth - 1, "CHANCE")            minEval = min(minEval, eval)        return minEval            elif nodeType == "CHANCE":        expectedEval = 0        for each child in node.children:            probability = get_probability(child)            eval = EXPECTIMINIMAX(child, depth - 1, next_strategic_player)            expectedEval = expectedEval + (probability * eval)        return expectedEval

Task 1 Solution: Static Tree Evaluation
The mathematical calculation for Task 1 is explicitly detailed below:
• Chance Node A Expected Value: (10 × 0.2) + (3 × 0.5) + (-2 × 0.3) = 2.0 + 1.5 - 0.6 = 2.9
• Chance Node B Expected Value: (5 × 0.4) + (8 × 0.4) + (0 × 0.2) = 2.0 + 3.2 + 0.0 = 5.2
• Root Node (MAX) Decision: max(Value(A), Value(B)) = max(2.9, 5.2) = 5.2
Hence, the expected optimal path leads to Chance Node B, yielding an expected value of 5.2.

Task 2 Solution: Stochastic Sticks Game
In this task, the game states dynamically transition based on intentional moves and chance interventions. The complete implementation features a strict recursive framework tracking `is_max` state-switching.
When the rule dictates that picking the final stick loses, the base condition values must accurately reflect who is forced to take the final stick.
If n = 0 (no sticks left): The player whose turn it is now has an empty pile because the previous player just extracted the last stick. The previous player loses, meaning the current player WINS.
If n = 1: The current player is forced to take the 1 remaining stick (since 1 is the minimum legal move). Taking it means they immediately lose.

Thus, the recursive depth architecture maps base evaluations as follows:
V(node) = +1if MAX wins (i.e., pile empty on MAX's turn or 1 stick left on MIN's turn)
V(node) = -1if MIN wins (i.e., pile empty on MIN's turn or 1 stick left on MAX's turn)

Conceptual Questions Guide
• Question 1 Guide: Standard Alpha-Beta pruning cannot be easily applied to an Expecti-Minimax tree without upper and lower bounds on the leaf nodes. This is because a chance node takes an average, and an unexplored child could have an extremely large or infinitely high value that shifts the entire average significantly. Pruning is only possible if we establish strict mathematical bounds (e.g., maximum possible utility U_max) to calculate the maximum possible value an unvisited branch could provide.
• Question 2 Guide: As slip probability increases to 50%, the action of choosing 2 sticks becomes highly volatile and less distinct from choosing 1 stick. The Maximizer agent will alter its behavior to avoid the 'Take 2' move if the lower-layer states of a slip lead to a losing state, shifting to a highly conservative or protective strategy to guarantee predictable state transitions.
